## 3. P0 — 联调阻断 / 用户可见故障

### 3.1 培训文档 URL 中文路径编码

**现象**：API 返回 `fileUrl` 如 `http://localhost:8100/assets/training/2026年门店制度手册PDF.pdf`，未编码时浏览器 `fetch` 可能 404；对文件名 `encodeURIComponent` 后可 200。

**建议（二选一或同时做）**：

- [ ] **后端**：`document_to_out` / `LocalStorageProvider.get_public_url` 对 path 分段 URL 编码（保留 `/`，只编码文件名段）
- [ ] **前端**：`getAssetUrl` 对 `http(s)://.../assets/` 后的路径做安全编码，或 `DocViewer` 请求前统一 `encodeURI` 逻辑

**验收**：

- [ ] 知识库 → 制度 / 店长培训等 → 预览至少 1 份中文文件名的 PDF
- [ ] 预览 1 份 DOCX（`docx-preview` 拉取成功）

### 3.2 静态资源就绪检查

**现象**：文档与门店图依赖仓库根目录 `storage/`，商品图多为 OSS 直链；环境不一致时「列表有数据、预览 404」。

- [ ] 在 `api/README.md` 或 seed 流程中明确：`python -m scripts.sync_public_assets`（或等价步骤）为联调前置
- [ ] 可选：`verify_connectivity.py` 增加 1～2 个 `HEAD /assets/training/...` 抽样（用 seed 中已知文件名）

### 3.3 目录加载失败时的用户提示

**现象**：`CatalogLoader` 在 `ensureCatalog()` 失败时仍 `setReady(true)`，页面可能空白列表且无说明。

- [ ] `ensureCatalog` 区分成功 / 失败，失败时展示「无法连接学习平台服务」+ 重试按钮
- [ ] 登录页也应提示 API 不可达（可选：健康检查 `GET /health`）

## 4. P1 — 会话与数据一致性

### 4.1 Access Token 过期与 Refresh

**现象**：后端已发 `refreshToken`，前端 401 仅 `clearTokens`；`JWT_ACCESS_MINUTES=30` 后需重新登录。

- [ ] 后端新增 `POST /auth/refresh`（校验 refresh JWT，签发新 access）
- [ ] 前端 `api/client.ts`：401 时尝试 refresh 一次再重放原请求；失败再跳转登录
- [ ] 登出时可选调用 `POST /auth/logout`（若后端后续做 token 黑名单）

**验收**：

- [ ] 等待或手动缩短 access 过期时间后，页面无感续期或仅一次轻提示

### 4.2 新闻已读 / 浏览数：去掉双写

**现象**：在线模式仍写 `newsReadStorage`（localStorage），与 `/news/read-status`、`/view` 并存。

- [ ] `newsService`：`USE_MOCK=false` 时仅走 API，不调用 `markNewsRead` / `incrementNewsView` 本地写
- [ ] 登录成功后 `initReadStatus` 为唯一已读来源；未登录不展示已读态（或提示登录）
- [ ] 迁移：首次上线可清空旧 key `caisedi_news_read_v1` / `caisedi_news_views_v1`（文档注明）

### 4.3 测验记录：在线模式以服务端为准

**现象**：`saveQuizAttempt` 在线时先本地 `unshift` 再异步 POST，失败时 UI 与服务器不一致。

- [ ] 提交测验：POST 成功后再更新内存缓存 / UI
- [ ] 草稿 `putQuizDraft` / `deleteQuizDraft` 失败时 toast 提示
- [ ] 登出时 `invalidateUserStateCache`

### 4.4 最近学习列表刷新

- [ ] `recordRecentLearning` POST 成功后 `await initRecentLearningFromApi()`，避免仅乐观更新 `apiCache`
- [ ] Dashboard 进入时若已登录且无缓存，主动拉一次 `/learning/recent`

## 5. P2 — API 契约与工程规范

### 5.1 OpenAPI 快照与前后端类型

- [ ] 定期导出：`curl http://localhost:8100/api/v1/openapi.json -o docs/api/openapi-v1.json`（见 `docs/api/README.md`）
- [ ] 可选：用 openapi-typescript 生成 `app/src/api/generated.ts`，减少手写 DTO 漂移
- [ ] 在 PR 检查中对比 openapi diff（有 breaking 则注明）

### 5.2 统一资源 URL 策略

| 资源类型 | 当前 | 建议 |
|----------|------|------|
| 商品图 | OSS 绝对 URL | 保持；文档约定 seed 字段格式 |
| 新闻封面 | API 映射 storage / 相对路径 | 与 `getAssetUrl` 规则写进 README |
| 培训文档 | `/assets/training/{filename}` | 必须编码；优先 `storage_key` 而非裸 filename |
| 门店相册 | `/assets/stores/...` | 联调清单中固定 3 个相册路径抽检 |

- [ ] 后端 `get_public_url` 统一编码辅助函数，避免各 mapper 各自实现

### 5.3 分类 / Tab 元数据

**现象**：文档分类、面料分类、测验模块标签仍在前端 `data/*` 硬编码；后台改 category 后前端筛选项可能对不上。

- [ ] 短期：seed 与前端 `*Categories` 常量对照表写在本文档或 seed 注释，改数据时同步改前端
- [ ] 中期：API 增加 `GET /documents/meta?tab=` 或 `GET /catalog/meta` 返回 categories / tabs
- [ ] 面料：`fabricCategories` 改为由 `/fabrics` 聚合 `category` 去重生成（前端派生）

### 5.4 资料更新页使用服务端筛选

**现象**：`content-updates` 支持 `action` / `type` / `q`，`Changelog.tsx` 全量拉取后前端过滤。

- [ ] 筛选 / 搜索变更时带 query 调 `fetchAll(params)`，减少 payload
- [ ] Dashboard 最近更新条数继续 `limit` 或后端 `?limit=6`（若后端支持）

### 5.5 未使用的详情接口（按需）

后端已有、前端用列表缓存即可；若要做深链 / 分享再接入：

- [ ] `GET /products/{id}`
- [ ] `GET /documents/{doc_id}`
- [ ] `GET /news/{news_id}`

## 8. 联调自检脚本（每次改完跑一遍）

```powershell
# 终端 1 — API
cd api
python -m scripts.seed --phase all    # 数据变更后执行
uvicorn app.main:app --reload --port 8100

# 终端 2 — 自检
cd api
python scripts/verify_connectivity.py

# 终端 3 — 前端（确认 app/.env 非 Mock）
cd app
npm run dev
```

**浏览器手工冒烟（建议 5 分钟）**：

| 步骤 | 检查点 |
|------|--------|
| 1 | Network 出现 `8100/api/v1/products`、`fabrics`、`news` |
| 2 | 登录 `KS20250001` / `123456`，`/auth/me` 200 |
| 3 | 商品页有图、面料详情可开 |
| 4 | 知识库 → 制度文档 → **预览中文 PDF** |
| 5 | 公司文化 → 门店相册图片加载 |
| 6 | 顶栏搜索「棉」有结果并跳转 |
| 7 | 完成一道测验 → 我的答题有记录；刷新仍在 |
| 8 | 新闻标记已读 → 未读数减少；换账号或清 token 行为符合预期 |
