## 1. 系统现状说明

### 1.1 这不是「大模型 AI 出题」

界面虽使用「知识测试」等文案与 Brain 图标，实现上为**规则自动组卷**，无 LLM 调用：

| 类型 | 实现方式 | 主要文件 |
|------|----------|----------|
| 面料测验 | 从面料字段拼单选题 + 正则解析 `quizzes` 原文 | `buildFabricQuizzes.ts`、`parseFabricQuizzes.ts` |
| 商品测验 | 从商品字段 + 全库作干扰项生成「看图题」 | `buildProductQuizzes.ts` |
| 抽题 / 判分 | 模块内全量 shuffle；集合相等判对错 | `knowledgeQuizPool.ts`、`KnowledgeQuizDialog.tsx` |
| 成绩 | 本地 + API（`/quiz-attempts`、`/quiz-drafts`） | `quizRecordsStorage.ts`、`userStateApi.ts` |

店员反馈「错漏百出」，主要来自：**题库构建时机错误、干扰项算法缺陷、看图题不可看图作答**，而非模型幻觉。

### 1.2 已具备的能力（可保留）

- [x] 按面料分类 / 商品系列 × 知识模块组织测验
- [x] 单选、多选（题干含「多选」或答案多 key）
- [x] 答题草稿、完成记录、我的答题页进度
- [x] 商品题支持配图与交卷后展示货号
- [x] 面料「课后测试」可复用教材内嵌习题原文（seed `quizzes` 字段）

## 2. 问题总览

| 编号 | 类别 | 现象 | 根因摘要 |
|------|------|------|----------|
| Q1 | 工程 | API 联调后测验无题或题量极少 | `knowledgeQuizPool.ts` 在 **import 时** 用空列表构建 `fabricPool` / `productPool`，之后不刷新 |
| Q2 | 工程 | 一次测验题量过大（几十～上百） | `getQuestionsForTagAndModule` 返回模块**全部**题目；`pickBalancedByModule` 未使用 |
| Q3 | 算法 | 选对仍判错 / 选项重复 | `buildMcq` 用截断文案作选项，`indexOf` 找正确答案；全库干扰项易碰撞 |
| Q4 | 设计 | 商品看图题「靠猜」 | 品名、货号、系列等多为文字属性，图上不可见；同款名 SKU 大量重复 |
| Q5 | 解析 | 部分面料课后题丢失 | `parseFabricQuizText` 仅支持固定行格式，格式偏差则静默跳过 |
| Q6 | 内容 | 自动题与人工题质量参差 | 规则生成题未标注；竞品对比、售后分段等解析脆弱 |
| Q7 | 产品 | 用户以为是 AI | 文案 / 图标暗示智能出题，实际为脚本组卷，预期落差大 |

## 4. P0 — 工程阻断（必须先修）

### 4.1 题库惰性构建（API 模式必做）

**现状**（`knowledgeQuizPool.ts`）：

```ts
const fabricPool = buildAllFabricQuizQuestions(fabricService.list())
const productPool = buildProductQuizQuestions()
```

模块首次加载时 `CatalogLoader` 往往尚未完成，`productService.list()` 为空 → `buildProductQuizQuestions` 因 `eligible.length < 8` 返回 `[]`，且**永不重建**。

**建议**：

- [ ] 删除顶层常量池，改为 `getQuizPool(source)` 内按需构建
- [ ] 增加 `invalidateQuizPool()`，在 `ensureCatalog()` 成功后调用
- [ ] 或监听 catalog ready 后再首次 import 测验模块（次选）

**验收**：

- [ ] 刷新页面、登录后进入知识页 → 各模块题数 > 0，与面料/商品数量级合理
- [ ] Network 中商品列表返回后再开始测验，题量不为 0

### 4.2 每轮固定抽题数量

**现状**：`getQuestionsForTagAndModule` → `shuffle` 后返回**全部**题目。

**建议**：

- [ ] 常量 `QUIZ_SESSION_SIZE = 10`（可配置 8～12）
- [ ] 使用已有 `pickBalancedByModule(pool, count)` 按模块轮询抽题
- [ ] 商品题可按 `productId` 去重，保证一轮不多款同图重复考同一属性
- [ ] UI 文案：「本轮 10 题 · 题库共 N 题」

**验收**：

- [ ] 完成「产品认知 · 合成纤维」一轮在 15 分钟内可做完（约 10 题）
- [ ] 模块卡片上的题数区分「题库总量」与「每轮题数」

### 4.3 修复 `buildMcq` 干扰项与判分

**现状问题**：

- 正确项与干扰项均 `truncate(..., 120)`，不同原料可能变成相同字符串
- `pool.filter(v => v !== correct)` 比较原文，选项比较截断文
- `labels.indexOf(correctLabel)` 在重复 label 时指向错误选项

**建议**：

- [ ] 选项结构改为 `{ key, label, valueId? }`，判分只认 `key`
- [ ] 干扰项按 `productCode` / `fabricCode` 去重，禁止与正确项同 label
- [ ] 有效干扰项不足 3 个时 **返回 null 跳过该题**，不硬凑四选项
- [ ] 单元测试：构造「成份相近」的两商品，断言不会出现两个 identical 选项

**验收**：

- [ ] 随机抽 30 道自动生成题，人工快检无重复选项、无「两个都像对的」
- [ ] 已知课后题（如 PU 第 1 题答案 B）判分正确

## 5. P1 — 出题质量与体验

### 5.1 商品「看图测验」题型收缩

**原则**：只考**能从主图分辨**的属性；考不到的改为非看图或取消。

| 题型 | 建议 |
|------|------|
| 颜色 | 保留（同系列多色款） |
| 面料成份 / 长描述 | 慎用；干扰项限同系列 |
| 工艺卖点 | 仅当视觉差异明显时保留 |
| 品名 | 暂停或改为「给货号选图」 |
| 货号 | 暂停「给图选货号」 |
| 系列 / 场景 / 版型 / 领型 | 默认关闭或改为文字测验（无图） |

**干扰项范围**：

- [ ] 由「全库 eligible」改为「同系列 + 同季节」优先，不足再扩圈
- [ ] 同名 `name` 的商品不作为彼此干扰项（无法区分）

### 5.2 面料自动题与人工题分层

| 来源 | 标记 | 建议 |
|------|------|------|
| `parseFabricQuizText`（`quizzes` 字段） | `origin: 'author'` | 视为权威题，优先展示 |
| `buildCoreFeatureQuestions` 等规则生成 | `origin: 'generated'` | UI 提示「练习题，以教材为准」；考核可仅计 author 题 |

- [ ] 模块「课后测试」以解析原文为主，减少重复机器题
- [ ] 其它模块限制每面料自动生成题上限（如 2 道）

### 5.3 正则解析加固或结构化

**现状**：`parseFabricQuizzes.ts` 要求 `1.` 题干、`A.` 选项、`答案：B` 或 `A、B、D`。

- [ ] 在 `api/seed_data/fabrics.json` 统一习题模板，提交前 lint
- [ ] 解析失败时打日志（dev）或上报计数，便于发现丢题
- [ ] 中期：seed 增加 `quizQuestions: []` JSON 数组，逐步弃用纯文本 `quizzes`

### 5.4 交卷与错题体验

- [ ] 结果页列出错题：题干 + 所选 + 正确答案 +「查看知识点」链接（面料详情 / 商品资料）
- [ ] 多选未选全时判错，提交前提示「本题多选」
- [ ] 文案调整：「知识测验」替代易误解的「AI 测试」；Brain 图标可换为 ClipboardCheck

### 5.5 竞品对比 / 售后等脆弱解析

- [ ] `parseComparisonDimensions`：解析失败则**不生成**该题（已有逻辑，需确认无 fallback 错题）
- [ ] `parseAfterSalesTips`：过滤过短行；优先用完整条目而非第一句分段
- [ ] 销售话术题：干扰项勿混入同场景的正确话术

## 6. P2 — 产品与内容治理

### 6.1 内容审阅流程（无代码也能先做）

- [ ] 导出当前自动生成题清单（可写 `scripts/dump-quiz-pool.ts`）
- [ ] 培训同事按模块勾选「保留 / 删除 / 需改写」
- [ ] 人工 `quizzes` 字段优先维护，机器题只做补充

### 6.2 测验策略配置

| 配置项 | 建议默认值 |
|--------|------------|
| 每轮题数 | 10 |
| 是否计入考核 | 仅 `origin: author` |
| 商品看图题开关 | 先关品名/货号类 |
| 及格线 | 70%（可模块级配置） |

### 6.3 与「我的答题」一致性

- [ ] 保存 attempt 时写入 `questionIds: string[]`，便于复盘同一套题
- [ ] 重试模块时重新抽题，分数与上一轮不可直接对比时在 UI 说明

## 8. P4 — 可选：AI 辅助出题

若未来引入 LLM，建议**不要**现场无校验生成：

```
教材段落 → LLM 生成候选 → 规则校验 → 人工抽检 → status=published
```

**规则校验示例**：

- 4 个选项、正确答案 key 存在于 options
- 答案能从引用段落逐字或同义找到
- 禁止与现有题库 prompt 高度重复

- [ ] 单独 Admin 工具，不在店员 App 内实时调模型
- [ ] 保留 `origin: author` 优先级高于 `origin: ai`

## 10. 验收标准（改完后自测）

| # | 步骤 | 通过标准 |
|---|------|----------|
| 1 | API 模式刷新 → 知识页 → 面料测验 | 各分类下模块题数 > 0 |
| 2 | 开始「产品认知 · 任一分类」 | 本轮约 10 题，非 50+ |
| 3 | 完成 PU「课后测试」原题 | 与教材答案一致（如第 1 题 B） |
| 4 | 商品测验颜色题（同系列） | 能凭图片区分，非纯猜品名 |
| 5 | 故意选错一题交卷 | 错题列表可读，可跳转知识详情 |
| 6 | 刷新后再测同一模块 | 题集可变化，记录中有 questionIds（若已实现 P2） |
| 7 | 断网或 API 未就绪进知识页 | 有明确提示，非静默 0 题 |

## 附录 A：`buildMcq` 问题示意

```
正确答案原文（200 字）  →  truncate → 选项 A
另一面料摘要前 120 字   →  truncate → 选项 A（碰撞）
判分：correctKey 指向第一个 A → 错题
```

**改法**：选项绑定唯一 id，label 仅展示，判分与去重基于 id。

## 附录 B：商品看图题不宜考的内容
